## 흐름

입장 → 홈. 홈/프로그램/체험/나의 참여는 동급 탭.
프로그램 → 신청형 상세 → 신청 확인 → 서버 성공 → 신청 결과 → 내 일정 → 신청 관리 → 취소 확인.
프로그램 → 자유 입장 상세 → 전체 시간표 (신청 흐름 없음).
체험 → 현장 안내 → QR 스캔 → 서버 적립 성공 → 결과 → 스탬프/보상.
나의 참여 → 내 일정 / 스탬프 / 보상. 내 일정0개는 빈 일정 상태.

## 공통 상태 계약

- loading: 요청이 끝나기 전에 완료·보상·신청 수량을 확정하지 않는다. 같은 요청을 중복 전송하지 않는다.
- empty: 다음 탐색 목적지를 제공한다. 실패를 데이터0개로 표시하지 않는다.
- error: 원래 입력과 선택을 유지하고 원인/재시도 제공. 새 오류 색·새 모달 디자인 금지.
- success: 서버 응답에 근거. 중복 QR·이미 신청·정원 마감·취소 실패는 성공으로 바꾸지 않는다.
- navigation: 목록으로 돌아오면 필터/스크롤을 보존. 상위 탭의 탐색 문맥을 유지.

## 미정: 임의 구현 금지

1. 개인 QR Q01 화면이 현재 페이지에 없다. 헤더 QR은 개인 QR 보여주기 용도이며 활동 QR 스캔 Q02로 바꾸면 안 된다. 기존 앱의 개인 QR 동작을 확인하고 화면 정의를 받은 뒤 연결한다.
2. 포토부스 대기 목적지는 링크만 있고 상세 화면 정의가 없다. 현재 기능을 조사해 매핑하되 새 대기 UI를 임의 디자인하지 않는다.
3. 앱 체험의 미니게임/아이디어/설문/갤러리 내부 화면은 이 패키지에 없다. 기존 기능을 유지하고 별도 화면 승인 후 재디자인.
4. 보상 관련 화면은 3개/4개 기준, 응모권/룰렛이 상충한다. 운영 기준 확정 전 증정 조건과 수량을 코딩하지 않는다.
5. 전시 예상 시간이 목록5분/안내15분으로 다르다. 운영 데이터에서 단일 값을 확정한다.
6. 카메라 거부 시 기본 카메라/담당자 적립 연결은 실제 인프라 확인이 필요하다. 존재하지 않는 경로를 정상 완료로 연결하지 않는다.

상세 문구는 pages.json의 copy와 스크린샷을 기준으로 확인한다. 날짜·장소·실명·잔여석·보상 개수는 모두 실제 데이터로 연결한다.
