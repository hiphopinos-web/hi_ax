# AX Festival · 바이브코딩 전달 패키지

버전: **AX-TDS-2026.09.21-v1** · Figma `2858:8`의 2026-09-21 추출본

동료에게 이 폴더 전체 또는 ZIP을 전달하세요. Figma 계정 없이 `index.html`을 브라우저에서 열면 21개 기준 화면과 규칙을 볼 수 있습니다.

## 시작 순서

1. ZIP을 압축 해제하고 `index.html`을 열어 기준 화면을 확인합니다.
2. 앱 저장소 안에 이 폴더를 `design-handoff/`라는 이름으로 넣습니다. 폴더 구조를 유지합니다.
3. `START-HERE-PROMPT.md` 전체를 바이브코딩 AI의 첫 메시지에 붙여 넣습니다.
4. 저장소의 기존 규칙을 보존하며 `AGENTS.md` 내용을 해당 저장소의 AI 지침에 병합합니다. 자동으로 읽는 파일명은 도구마다 다르므로 첫 프롬프트에도 명시합니다.
5. 로그인 → 홈 → 프로그램 → 체험 → 나의 참여 순으로, 한 화면씩 구현·비교합니다.
6. `python3 design-handoff/tools/check_design.py --ui-root src/ax-ui`를 실행합니다. 경로는 실제 새 UI 전용 폴더로 바꿉니다. 실패하면 완료로 보고하지 않습니다.

## 무엇을 고정했나요?

- `DESIGN-CONTRACT.md`: 색상 역할, 정보 위계, 타이포, 간격, 컴포넌트, 금지 사항.
- `PAGES.md`: 페이지 목적·진입·행동·상태·미정 항목. 화면 이름의 중복을 구현 키로 구분.
- `design-system/`: 실제 Figma에서 추출한 토큰과 재사용 CSS. 프레임워크 독립형.
- `reference/screens/`: 현재 앱 화면 21개. 발표용 10장이나 초기 M3 시안은 기준이 아닙니다.
- `assets/`: Pretendard Variable, 원본 QR 모서리·내비게이션 SVG, 로그인 모션/정지 포스터.
- `QA.md`: 화면/행동 검수 기준과 미해결 정책. `lock.json`: 파일 변조 감지.
- `examples/login.html`: 기본 컴포넌트를 조합하는 예시. 실제 인증 기능은 앱에 연결해야 합니다.

## 강제 수준과 한계

AI 프롬프트만으로 디자인 변형을 완전히 막을 수는 없습니다. 이 패키지는 기준 파일 잠금 + 페이지별 스타일 금지 + 검사 + 화면 비교를 함께 사용합니다. 검사기는 규칙 우회를 모두 탐지하는 보안 도구가 아니며, 정보 순서·실제 접근성·동작 검수는 QA를 병행해야 합니다. CI에 검사 명령을 필수로 연결하고 기준 파일 변경은 디자인 담당자 리뷰를 받으세요. 이 패키지는 아직 실제 앱 저장소/CI에 설치된 상태가 아닙니다.

미정 기능은 전체 작업을 멈출 이유가 아닙니다. 정의된 화면을 먼저 구현하고 `QA.md`의 차단 항목에 해당하는 기능만 보류합니다. 새 색/새 화면/보상 수치로 임의 해결하지 않습니다.
