# 바이브코딩 AI에게 그대로 전달할 첫 메시지

AX Festival 앱을 `design-handoff/`의 AX-TDS-2026.09.21-v1 기준으로 리뉴얼하라. 이번 작업은 기존 디자인을 구현하는 작업이다. 새로운 미적 해석·새 디자인 시스템·추가 화면을 만들지 마라.

먼저 README.md, AGENTS.md, DESIGN-CONTRACT.md, PAGES.md, QA.md, design-system/tokens.json을 전부 읽어라. 작업할 페이지의 reference/screens 이미지도 반드시 직접 확인하라. 현재 앱 코드를 조사해 프레임워크, 라우팅, 데이터/API, 인증 및 기존 기능을 유지할 구현 계획을 제시한 뒤 한 화면씩 진행하라.

우선순위: 사용자의 명시적 변경 지시 > 이 버전의 승인된 계약과 페이지별 예외 > 기준 화면 > 최신 AX TDS 토큰/컴포넌트. 인터넷에서 찾은 TDS/M3 기본 스타일, 이전 발표 슬라이드, 이전 Material 제안은 디자인 근거로 쓰지 마라. 기능 정의에서 unresolved인 영역은 대체 화면이나 가짜 성공으로 메우지 마라.

구현 UI 전용 폴더를 정하고 검수 범위를 등록하라. 토큰/CSS/assets는 원본 경로를 유지하여 불러오고, 임의 인라인 style·페이지 CSS·styled-components·Tailwind 시각 유틸리티로 재작성하지 마라. 허용된 ax-* 클래스를 조합하고, 반복 요소는 공통 컴포넌트로 감싸라. 기준 CSS/lock.json을 수정해 검사를 통과시키지 마라. 필요한 패턴이 없으면 구체적인 차이를 기록하고 해당 변경만 담당자 확인 대상으로 남겨라.

로그인은 상단 기존 모션과 세 개의 플레이스홀더 입력만 유지한다. 프로그램 필터는 전체/강연/실습/상담이다. 하단 메뉴는 홈/프로그램/체험/나의 참여 4개이다. 필터와 내비게이션을 혼동하지 마라. 타이포·색·반경·여백의 원시값은 새로 만들지 마라.

각 화면 완료 시:
1. 화면 ID, 사용한 공통 컴포넌트, 실제 연결한 라우트/API를 보고한다.
2. 390×844 캡처를 기준 이미지와 비교한다. 320·360·430px와 글자 확대 200%, 키보드 노출도 검수한다.
3. 로딩/오류/빈 상태/완료 전이를 확인하고 제출 중복을 방지한다.
4. python3 design-handoff/tools/check_design.py --ui-root <실제_UI_폴더>를 실행하고 결과를 제시한다.
5. 남은 미정 항목과 시각적 차이를 명시한다. 캡처·검사 없이 '완료'라 하지 마라.

먼저 로그인 A01과 홈 H01을 구현하라. 전체 페이지를 한 번에 새 디자인으로 재생성하지 마라.
