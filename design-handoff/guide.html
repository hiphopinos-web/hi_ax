버전: AX-TDS-2026.09.21-v1 · Figma 2858:8의 2026-09-21 추출본

동료에게 이 폴더 전체 또는 ZIP을 전달하세요. Figma 계정 없이 index.html을 브라우저에서 열면 21개 기준 화면과 규칙을 볼 수 있습니다.

시작 순서

1. ZIP을 압축 해제하고 index.html을 열어 기준 화면을 확인합니다.

2. 앱 저장소 안에 이 폴더를 design-handoff/라는 이름으로 넣습니다. 폴더 구조를 유지합니다.

3. START-HERE-PROMPT.md 전체를 바이브코딩 AI의 첫 메시지에 붙여 넣습니다.

4. 저장소의 기존 규칙을 보존하며 AGENTS.md 내용을 해당 저장소의 AI 지침에 병합합니다. 자동으로 읽는 파일명은 도구마다 다르므로 첫 프롬프트에도 명시합니다.

5. 로그인 → 홈 → 프로그램 → 체험 → 나의 참여 순으로, 한 화면씩 구현·비교합니다.

6. python3 design-handoff/tools/check_design.py --ui-root src/ax-ui를 실행합니다. 경로는 실제 새 UI 전용 폴더로 바꿉니다. 실패하면 완료로 보고하지 않습니다.

무엇을 고정했나요?

- DESIGN-CONTRACT.md: 색상 역할, 정보 위계, 타이포, 간격, 컴포넌트, 금지 사항.

- PAGES.md: 페이지 목적·진입·행동·상태·미정 항목. 화면 이름의 중복을 구현 키로 구분.

- design-system/: 실제 Figma에서 추출한 토큰과 재사용 CSS. 프레임워크 독립형.

- reference/screens/: 현재 앱 화면 21개. 발표용 10장이나 초기 M3 시안은 기준이 아닙니다.

- assets/: Pretendard Variable, 원본 QR 모서리·내비게이션 SVG, 로그인 모션/정지 포스터.

- QA.md: 화면/행동 검수 기준과 미해결 정책. lock.json: 파일 변조 감지.

- examples/login.html: 기본 컴포넌트를 조합하는 예시. 실제 인증 기능은 앱에 연결해야 합니다.

강제 수준과 한계

AI 프롬프트만으로 디자인 변형을 완전히 막을 수는 없습니다. 이 패키지는 기준 파일 잠금 + 페이지별 스타일 금지 + 검사 + 화면 비교를 함께 사용합니다. 검사기는 규칙 우회를 모두 탐지하는 보안 도구가 아니며, 정보 순서·실제 접근성·동작 검수는 QA를 병행해야 합니다. CI에 검사 명령을 필수로 연결하고 기준 파일 변경은 디자인 담당자 리뷰를 받으세요. 이 패키지는 아직 실제 앱 저장소/CI에 설치된 상태가 아닙니다.

미정 기능은 전체 작업을 멈출 이유가 아닙니다. 정의된 화면을 먼저 구현하고 QA.md의 차단 항목에 해당하는 기능만 보류합니다. 새 색/새 화면/보상 수치로 임의 해결하지 않습니다.

바이브코딩 AI에게 그대로 전달할 첫 메시지

AX Festival 앱을 design-handoff/의 AX-TDS-2026.09.21-v1 기준으로 리뉴얼하라. 이번 작업은 기존 디자인을 구현하는 작업이다. 새로운 미적 해석·새 디자인 시스템·추가 화면을 만들지 마라.

먼저 README.md, AGENTS.md, DESIGN-CONTRACT.md, PAGES.md, QA.md, design-system/tokens.json을 전부 읽어라. 작업할 페이지의 reference/screens 이미지도 반드시 직접 확인하라. 현재 앱 코드를 조사해 프레임워크, 라우팅, 데이터/API, 인증 및 기존 기능을 유지할 구현 계획을 제시한 뒤 한 화면씩 진행하라.

우선순위: 사용자의 명시적 변경 지시 > 이 버전의 승인된 계약과 페이지별 예외 > 기준 화면 > 최신 AX TDS 토큰/컴포넌트. 인터넷에서 찾은 TDS/M3 기본 스타일, 이전 발표 슬라이드, 이전 Material 제안은 디자인 근거로 쓰지 마라. 기능 정의에서 unresolved인 영역은 대체 화면이나 가짜 성공으로 메우지 마라.

구현 UI 전용 폴더를 정하고 검수 범위를 등록하라. 토큰/CSS/assets는 원본 경로를 유지하여 불러오고, 임의 인라인 style·페이지 CSS·styled-components·Tailwind 시각 유틸리티로 재작성하지 마라. 허용된 ax-* 클래스를 조합하고, 반복 요소는 공통 컴포넌트로 감싸라. 기준 CSS/lock.json을 수정해 검사를 통과시키지 마라. 필요한 패턴이 없으면 구체적인 차이를 기록하고 해당 변경만 담당자 확인 대상으로 남겨라.

로그인은 상단 기존 모션과 세 개의 플레이스홀더 입력만 유지한다. 프로그램 필터는 전체/강연/실습/상담이다. 하단 메뉴는 홈/프로그램/체험/나의 참여 4개이다. 필터와 내비게이션을 혼동하지 마라. 타이포·색·반경·여백의 원시값은 새로 만들지 마라.

각 화면 완료 시:

1. 화면 ID, 사용한 공통 컴포넌트, 실제 연결한 라우트/API를 보고한다.

2. 390×844 캡처를 기준 이미지와 비교한다. 320·360·430px와 글자 확대 200%, 키보드 노출도 검수한다.

3. 로딩/오류/빈 상태/완료 전이를 확인하고 제출 중복을 방지한다.

4. python3 design-handoff/tools/check_design.py --ui-root <실제_UI_폴더>를 실행하고 결과를 제시한다.

5. 남은 미정 항목과 시각적 차이를 명시한다. 캡처·검사 없이 '완료'라 하지 마라.

먼저 로그인 A01과 홈 H01을 구현하라. 전체 페이지를 한 번에 새 디자인으로 재생성하지 마라.

디자인 계약 · AX-TDS-2026.09.21-v1

1. 기준과 충돌 해결

기준은 Figma 2858:8의 2026-09-21 추출본이다. 이 패키지의 이미지/JSON은 시점 고정 스냅샷이며 Figma의 이후 편집을 자동 반영하지 않는다. AX TDS/* 스타일과 VariableID:2858:*만 사용한다. AX UI 제안/*, 초기 2846:* Material 토큰, 발표용 블랙 배경은 앱에 섞지 않는다. TDS에서 영향을 받은 AX의 커스텀 시스템이며 Toss 공식 컴포넌트 패키지를 그대로 구현했다는 의미는 아니다.

실제 화면별 재정의가 컴포넌트 원본보다 우선한다. 대표적으로 로그인은 TextField/Default 라이브러리에 있는 외부 라벨/도움말을 사용하지 않고 실제 A01의 56px 필드만 사용한다. 이미지와 규칙이 충돌하면 해당 화면만 확인 항목으로 기록한다.

2. 정보 구조

하단 최상위 메뉴는 홈 / 프로그램 / 체험 / 나의 참여 순서로 고정한다. 스탬프·보상·내 일정은 나의 참여의 하위 목적지다. QR은 유틸리티이며 다섯 번째 탭이 아니다. 홈은 현재 할 일, 프로그램은 탐색/신청, 체험은 활동 시작, 나의 참여는 개인 기록에 집중한다. 상세 화면에 전체 목록/보상/프로필을 다시 몰아넣지 않는다.

한 화면의 주 행동은 하나다. 보조 행동은 Weak 버튼/텍스트로 구분한다. 신청은 상세 → 확인 → 결과 → 내 일정으로 이어진다. 자유 입장 프로그램에 신청 버튼을 추가하지 않는다. 최신 P01 필터는 전체 / 강연 / 실습 / 상담이다. 층수는 목록의 정보 배지이며 필터 탭으로 바꾸지 않는다.

3. 레이아웃·반응형

- Figma 기준 뷰포트 390×844, 본문 좌우 24, 가용 폭 342, 섹션 간격 24.

- 상단 바 64, 최상위 하단 내비게이션 80. 스크롤은 본문에만 주고 고정 행동이 본문을 가리지 않는다.

- 내용 내부는 4/8/12/16/20/24/32/40/48/64 및 0만 사용. 장식용 예외 간격 금지.

- 카드 반경24, 목적지 행20, 버튼16, 입력12, 시트 상단32. 토큰에 있는 다른 반경은 해당 기준 화면에 쓰인 경우만 사용.

- 본문/카드는 내용에 따라 늘어난다. 844px를 앱 전체 고정 높이로 쓰거나 글자를 줄여 맞추지 않는다.

- 웹 구현 보완 규칙: 320–480px는 단일 열, 480px 초과는 최대480px 앱 컨테이너를 중앙 배치한다. 이는 Figma의 별도 데스크톱 시안이 아니라 전달용 기본 방침이다. 별도 데스크톱 재배열은 승인 전 추가하지 않는다.

- safe-area는 하단에 반영한다. 키보드가 뜨면 입력 및 제출 동작에 접근 가능해야 한다. 가로 스크롤/줄임표로 필수 정보를 숨기지 않는다.

6. 컴포넌트 규격

- Primary 버튼: 높이 최소56, 반경16, T5 strong, brand/onBrand. 로딩·비활성 중 중복 요청 방지, 라벨 위치 유지.

- Weak 버튼: 동일 형상, brandSoft/brandText. Primary와 동급의 시각 강조를 주지 않는다.

- 로그인 입력: 최소56, 반경12, 패딩16, inset/divider 1px, T7/body 플레이스홀더. 세 입력 간격20. 외부 상시 라벨/설명/입력 아이콘 없음. 접근성 이름은 숨김 label로 제공하고 오류 시에만 필드 옆 오류 설명을 연결한다.

- 목적지 행: 기준 최소80, 반경20, 패딩20, 제목·설명과 우측 상태/보기. 확대 시 높이는 늘어난다.

- 프로그램 행: 좌측48×48 층 배지, 간격16, 상하20, 제목→설명→일시/장소→상태 순. 기본 행은 카드 그림자 없음.

- 헤더 QR: 터치48×48, 그림32×32, 둥근 열린 모서리와 중앙QR13/600. 제공 SVG와 텍스트를 조합. 사각 QR 픽셀 그림이나 원형 버튼으로 교체 금지.

- 내비게이션: 4등분, 아이콘24, 라벨12/18, 간격4. 선택 상태를 색과 aria-current로 표시. 제공 SVG 사용.

- 로그인 모션: 상단342:160 비율, 원본 모션을 사용. 사용자의 동작 줄이기 설정에서는 정지 포스터. 새 3D/랜덤 도형 모션으로 대체 금지.

7. 깊이·인터랙션

기본 구분은 회색 바탕/흰 표면/내부 inset으로 만든다. 홈 주요 카드만 0 4 16 / 약4% 그림자, 시트는 0 16 48 / 약16%. 모든 카드에 그림자를 추가하지 않는다. 취소는 명시적 확인 시트 후 실행하고 실패 시 기존 신청 상태를 보존한다.

현재 Figma가 정의하지 않은 focus/loading/error 구현에는 기존 색/간격을 재사용한다. 전달용 focus 규칙은 ink 2px outline +4px offset이다. 이것은 접근성 구현 보완 규칙이며 원본 Figma 토큰으로 가장하지 않는다. 시트 포커스 고정·Escape닫기·닫은 후 트리거 복귀, 버튼 키보드 조작을 구현한다.

8. 변경과 검수

색상 값이 같아도 페이지 파일에 hex를 쓰지 않는다. 의미 토큰 또는 승인된 클래스를 쓴다. 다른 UI 키트의 기본 테마는 끈다. 컴포넌트가 부족하면 승인된 기존 패턴으로 해결 가능한지 먼저 확인하고 불가능한 패턴만 변경안으로 올린다.

변경안에는 대상 화면/기존값/제안값/필요한 이유/비교 캡처를 포함한다. 승인 후에만 기준 버전과 잠금 해시를 함께 갱신한다. 새 디자인이 예쁘다는 이유는 기존 계약을 바꾸는 근거가 아니다.

아이콘 구현 연결

원본 SVG는 reference 용도로 보존했다. assets/icons.svg는 같은 경로를 currentColor로 정규화한 구현용 스프라이트다. .ax-nav-link 안에 .ax-icon SVG와 <use href=".../assets/icons.svg#nav-home">을 배치한다. 나머지 키는 nav-program, nav-experience, nav-my. 각 SVG는 aria-hidden="true", 버튼/링크에는 실제 기능 이름을 제공한다. img로 원본 SVG를 직접 넣으면 원본 선택 색이 고정되므로 선택 상태 구현에는 스프라이트를 쓴다.

QR은 .ax-qr 안에 32px 원본 qr-corners.svg 이미지와 .ax-qr-label의 QR 텍스트를 겹친다. 버튼 접근성 이름은 '내 QR 보여주기'. Q02 활동 QR 스캔과 구분한다.

공통 상태 계약

- loading: 요청이 끝나기 전에 완료·보상·신청 수량을 확정하지 않는다. 같은 요청을 중복 전송하지 않는다.

- empty: 다음 탐색 목적지를 제공한다. 실패를 데이터0개로 표시하지 않는다.

- error: 원래 입력과 선택을 유지하고 원인/재시도 제공. 새 오류 색·새 모달 디자인 금지.

- success: 서버 응답에 근거. 중복 QR·이미 신청·정원 마감·취소 실패는 성공으로 바꾸지 않는다.

- navigation: 목록으로 돌아오면 필터/스크롤을 보존. 상위 탭의 탐색 문맥을 유지.

미정: 임의 구현 금지

1. 개인 QR Q01 화면이 현재 페이지에 없다. 헤더 QR은 개인 QR 보여주기 용도이며 활동 QR 스캔 Q02로 바꾸면 안 된다. 기존 앱의 개인 QR 동작을 확인하고 화면 정의를 받은 뒤 연결한다.

2. 포토부스 대기 목적지는 링크만 있고 상세 화면 정의가 없다. 현재 기능을 조사해 매핑하되 새 대기 UI를 임의 디자인하지 않는다.

3. 앱 체험의 미니게임/아이디어/설문/갤러리 내부 화면은 이 패키지에 없다. 기존 기능을 유지하고 별도 화면 승인 후 재디자인.

4. 보상 관련 화면은 3개/4개 기준, 응모권/룰렛이 상충한다. 운영 기준 확정 전 증정 조건과 수량을 코딩하지 않는다.

5. 전시 예상 시간이 목록5분/안내15분으로 다르다. 운영 데이터에서 단일 값을 확정한다.

6. 카메라 거부 시 기본 카메라/담당자 적립 연결은 실제 인프라 확인이 필요하다. 존재하지 않는 경로를 정상 완료로 연결하지 않는다.

상세 문구는 pages.json의 copy와 스크린샷을 기준으로 확인한다. 날짜·장소·실명·잔여석·보상 개수는 모두 실제 데이터로 연결한다.

구현 완료 판정

자동 게이트

python3 design-handoff/tools/check_design.py --ui-root src/ax-ui

- 동결 파일 해시 불일치: 실패.

- UI 폴더 내 새 CSS/SCSS/LESS, style 속성/태그, CSS-in-JS, 원시 색, 허용 외 클래스: 실패.

- 동적 className은 검사기가 값 전체를 보증할 수 없으므로 별도 수동 검토 경고. 가능하면 승인 클래스의 정적 분기를 사용.

- 이 검사는 구문 기반 보조 검사다. 빌드에 주입된 전역 CSS, 런타임 클래스, iframe, 외부 스타일 등의 모든 우회를 보증하지 않는다. CI 필수 실행과 담당자 리뷰가 필요하다.

- CI 예시: python3 design-handoff/tools/check_design.py --ui-root src/ax-ui → 앱 기존 lint/test/build → 시각 비교. 실제 CI 설정은 앱 저장소에 맞게 연결해야 한다.

시각 확인 — 각 화면 필수

- 390×844 / DPR1 기준으로 폰트 로드 후 캡처하고 reference/screens 원본과 나란히 비교. 동적 텍스트는 고정된 테스트 데이터 사용.

- 메뉴 순서, 섹션 순서, 색상 역할, 폰트 크기/굵기, 좌우24, 버튼56, 입력56, QR48/32가 일치.

- 일반 텍스트 렌더링 차이는 고려하되 요소 위치/크기 차이2px 초과는 원인 기록. 토큰값 차이는 허용하지 않음.

- 320·360·430px 및 글자200%에서 잘림/가로스크롤/행동 가림 없음. 큰 글자에서 높이가 늘어나는 것은 허용.

- 긴 프로그램명, 긴 이름, 빈 값, 오류 문장에도 제목·버튼·상태가 겹치지 않음.

- 키보드 노출 중 현재 입력과 제출 버튼에 접근 가능. 모션 줄이기 시 정지 이미지 제공.

행동 확인

- 모든 탭/상세/뒤로가기/필터 이동. 뒤로가기 시 필터와 스크롤 유지.

- 로그인 빈 입력·잘못된 정보·통신 오류·성공. 숨김 label, 오류 aria-describedby 연결.

- 신청 중복 클릭, 정원 마감, 이미 신청, 네트워크 실패. 성공 응답 전 완료 화면 금지.

- 취소 확인에서 유지/취소, 취소 실패 시 신청 유지. 시트의 포커스 이동/복귀 확인.

- QR 권한 허용/거부, 잘못된 코드, 이미 적립, 만료, 네트워크 오류. 서버 적립 전 보상 표시 금지.

- 내 일정0/1/다수, 보상0/사용완료, 긴 목록 스크롤.

- 키보드, 스크린리더 이름, 포커스, 텍스트 대비 확인. 아이콘만으로 의미 전달 금지.

릴리스 차단 항목

보상 조건 상충 / 누락된 개인 QR 화면 / 미정 포토부스 및 앱 체험 상세는 기능별 미해결로 기록한다. 정의된 화면의 구현은 계속 가능하지만 이 부분을 가짜 기능으로 완료 처리하지 않는다.

AX Festival UI 작업 계약

이 지침은 이 패키지를 사용하는 AX Festival UI 범위에 적용한다. 명시적인 사용자 지시가 가장 우선한다.

- 반드시 DESIGN-CONTRACT.md, PAGES.md, QA.md와 대상 reference/screens 이미지를 읽는다.

- design-system, assets, reference, lock.json은 동결된 입력이다. 기능 작업 중 수정하지 않는다.

- 새 UI는 하나의 검수 대상 폴더에 모은다. 공유 컴포넌트도 검사 범위에 포함한다.

- UI 시각 스타일은 design-system/tokens.css 및 components.css만 사용한다. 다른 CSS, CSS-in-JS, 인라인 style, 임의 유틸리티, 외부 테마 주입 금지.

- 구현은 의미 있는 HTML과 공통 컴포넌트 조합으로 한다. 이미지 한 장으로 전체 UI를 구현하지 않는다.

- 새 색, 자간, 폰트, 그림자, 그라데이션, 반경, 아이콘 세트, 메뉴, 페이지 추가는 별도 변경안으로 기록한다.

- 원본 기능/API/인증/검증을 추정으로 바꾸지 않는다. 예시 이름·수치·신청 상태는 데이터로 대체한다.

- unresolved 기능은 앱의 기존 구현과 정책을 확인하되, 정책·화면을 추정 생성하지 않는다.

- 테스트를 통과시키려고 기준 파일, 검사기, lock.json 또는 캡처 기준을 변경하지 않는다.

- 각 페이지마다 디자인 검사, 실제 화면 비교, 키보드 및 오류 경로 확인을 수행한다.

- 디자인 변경이 명시적으로 승인되면 새로운 버전으로 규칙·코드·기준 이미지·lock을 함께 업데이트하고 변경 기록을 남긴다.
